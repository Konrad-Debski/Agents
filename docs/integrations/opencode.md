# OpenCode

OpenCode gets a symlink of the global `AGENTS.md` in `${XDG_CONFIG_HOME:-~/.config}/opencode`. It reads skills directly from `~/.agents/skills`, with no extra copies. We detect it by the `opencode` program in `PATH` or an existing XDG configuration directory.

The OpenCode adapter updates `opencode.jsonc` if it exists, and `opencode.json` otherwise. A new file uses the OpenCode 2 `mcp.servers` section. Existing non-empty flat `mcp` maps keep the OpenCode 1 compatibility format. Changes touch only managed entries and keep JSONC comments, trailing commas, local MCP servers and other settings, including timeouts. When both files exist, the adapter also checks the second one for collisions, because OpenCode loads both configurations.

Stdio servers get `type: local`, a `command` array and optional `environment`. HTTP servers get `type: remote`, `url` and optional `headers`. Variables use the `{env:NAME}` syntax. The adapter does not copy OAuth credentials or secret values. It does not add `enabled` or `disabled` fields, whose format differs between releases. The separate `OPENCODE_CONFIG`, `OPENCODE_CONFIG_DIR` and `OPENCODE_CONFIG_CONTENT` layers, and the project configuration, can override global settings. The adapter does not modify these layers. `apply` and `doctor` report which extra configuration variables are set. The environment variables that select the configuration must be the same in the terminal, T3 and the synchronization service.
